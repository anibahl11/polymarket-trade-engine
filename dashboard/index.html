Market Selection

Asset MARKET_ASSET
Which crypto asset's Up/Down markets to trade. Determines the Polymarket slug prefix, price feed source, and order book to watch. Changing this switches the entire universe of markets the engine considers.
Market Window MARKET_WINDOW
Resolution window for each round. 5m = 5-minute BTC price prediction markets (faster cycles, more rounds per hour, less time in each position). 15m = slower, more time for price to move, fewer but longer-lived rounds.

Risk Gates — apply in both sim and live mode

Simulation Mode SIMULATION_MODE
Master safety switch. When ON (recommended default), all orders are simulated — no real money moves. Turn OFF only when also running with the --prod CLI flag and a funded on-chain wallet. Reflected as the PAPER TRADING / LIVE MONEY banner across the dashboard.
Starting Wallet Balance WALLET_BALANCE
$
Virtual bankroll in USD for paper trading sessions. This is the baseline all Session PnL, return %, and position sizing calculations use. Has no effect in live (--prod) mode — live mode reads your actual on-chain pUSD balance at startup.
Max Session Loss MAX_SESSION_LOSS
$
Hard stop: the engine shuts itself down when cumulative session losses reach this dollar amount. E.g. 3 = stop after losing $3 this session. This counter resets when you restart the engine. Prevents runaway losses in a single run.
Max Position Size MAX_POSITION_PCT
Maximum fraction of your wallet risked on a single buy order. E.g. 0.05 = 5% means on a $50 wallet you can spend at most $2.50 per entry. Smaller values = more conservative per-trade sizing, more rounds before a total loss is possible. Strategy-level position sizing is also capped by this value.
Max Drawdown MAX_DRAWDOWN_PCT
Circuit breaker: shuts the engine down if total session drawdown from your starting balance exceeds this fraction. E.g. 0.20 = stop if you're down 20% from the starting balance. Acts as a last-resort guard against a strategy going badly wrong.
Daily Loss Limit DAILY_LOSS_LIMIT
$ (0 = disabled)
Cumulative dollar loss cap for the current UTC day. Persists across engine restarts within the same day — the engine refuses to start if today's losses already exceed this limit. E.g. 5 = no more trading today once you've lost $5. Set to 0 to disable entirely.

Sim Realism — paper trading only, ignored in live mode

Partial Fill Probability SIM_PARTIAL_FILL_PROB
Probability (0–1) that a simulated buy order fills only partially instead of the full requested size. E.g. 0.2 = 20% chance your order is only partially filled, simulating real-world thin liquidity or competing orders. 0 = always fill fully (optimistic).
Slippage SIM_SLIPPAGE_BPS
basis points
Simulated taker price slippage applied to each fill, in basis points (1 bps = 0.01%). E.g. 20 = 0.20% worse price than the quoted best ask, mimicking the real cost of walking the order book. Adds friction to entries that makes sim returns more realistic. 0 = no slippage.
Latency Jitter SIM_LATENCY_JITTER_MS
milliseconds
Random latency added to simulated order submissions, in milliseconds. E.g. 200 = up to 200ms delay before an order is "acknowledged" by the sim client. Models real-world network variance and API round-trip time. Useful for testing time-sensitive entry logic. 0 = instant execution.
Network Failure Rate SIM_NETWORK_FAIL_PROB
Probability (0–1) that a simulated order submission fails entirely, as if the API returned an error or timed out. E.g. 0.05 = 5% of orders are rejected. Tests whether the engine handles rejections gracefully and retries or skips correctly. 0 = orders never fail.
Changes take effect on next engine restart.
